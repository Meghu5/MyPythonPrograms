docker build -t banking-qa:v1 -> Build the automation image
docker images ---- List local images
docker run --name qa-test banking-qa:v1 ----Create and start a test container 
docker ps ----List running containers
docker ps -a ----Include stopped containers
docker logs qa-test ----Inspect test output
docker logs -f qa-test ---- Follow live logs
docker exec -it qa-test sh ---- Open a shell in a running container
docker stop qa-test ---- Gracefully stop a running container
docker rm qa-test ---- Remove a stopped container
docker inspect qa-test ----Inspect container configuration and state

Important: docker exec requires a running container. If your test container exits, inspect its logs 
instead. Avoid --rm while debugging if you need to retain the stopped container for inspection.


“I first check the container status and exit code, then review its logs. I verify the entry-point command, 
required environment variables, dependency installation, mounted files, and permissions. 
I also check whether the process is designed to run as a one-off task. An automation container
 exiting after the test suite completes can be expected behavior.”

docker ps -a
docker logs banking-test
docker inspect banking-test

Example causes:

pytest returns a nonzero exit code because a test failed.
The application cannot connect to its API.
A required environment variable is missing.
The container's startup command is incorrect.

docker stop: requests graceful termination, then forcefully terminates after the configured grace period.

docker kill: sends a termination signal immediately by default.

docker rm: removes a stopped container; it is not a substitute for stopping a running container unless forced.

“Container filesystems are ephemeral, and a container removed with --rm cannot be used later 
to retrieve its internal files. I make test results durable by writing them to a mounted volume or
 uploading them to CI artifact storage. I configure the pipeline to publish reports even when tests fail,
  and capture screenshots, traces, and logs during test teardown or failure hooks.”
   
  Run the container with a mounted reports directory:

docker run --name banking-qa \
  -v "$PWD/reports:/app/reports" \
  banking-qa:v1
For Kubernetes, options include:
